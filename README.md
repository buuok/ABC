# 声音统一（voice-unify）原型

把多段录音或视频的**音量**、**音色**和**音高**调成一致，并**消除底噪**。可以选一段作为主音色，其余几段向它靠拢；视频处理后画面不动，只替换音轨。特别适合同一个 AI 配音音色、不同次生成的片段前后听起来不一样的情况。完全离线，只用 Node.js 标准库，没有任何第三方依赖，不访问网络。

## 双击即用的独立版（不用装任何东西）

下载对应系统的压缩包，解压后双击即可，浏览器会自动打开操作界面，关闭程序窗口即退出：

- Windows 10/11（64 位）：`VoiceUnify-Windows.zip` → 双击 `VoiceUnify.exe`。首次如出现“Windows 已保护你的电脑”，点“更多信息 → 仍要运行”。
- Mac 苹果芯片：`VoiceUnify-Mac-AppleSilicon.zip`；Mac Intel：`VoiceUnify-Mac-Intel.zip` → 首次在 `声音统一.command` 上右键 → 打开（macOS 15 起需到“系统设置 → 隐私与安全性 → 仍要打开”）。

界面按 1→2→3→4 四步走：添加文件（可整批、可选整个文件夹）→ 选主音色 → 选方案 → 开始处理。
- **一键预设**（`lib/presets.mjs`）：AI 配音统一（推荐，即“B 不升调”）、轻度统一、嘈杂录音、只统一音量、已拼好的成片（逐句）、强力统一（含音高）。参数藏在“高级设置”里。
- **音量**默认“跟主音色一样响”（命令行 `--lufs ref`），也可选 -16 / -14 / -23 LUFS。
- **批量和进度条**：处理在后台分步进行，进度条显示当前步骤和第几个文件；结果自动保存到“输出/日期时间/”文件夹，有“打开输出文件夹”按钮。
- **常用主音色**：把某段的音色特征存起来（`数据/常用主音色.json`），以后不用再带上那段录音。
- **手动调音色**（`lib/manual.mjs`）：每个文件一个“🎚 调音色”面板，五个滑块：音调（±6 半音）、嗓音粗细（共振峰 ±15%，不改音高）、厚度（200 Hz 低架）、清晰度（3 kHz 峰值）、明亮（8 kHz 高架），可单独试听、套用到所有文件，或按主音色给出建议值。手动调整在自动统一之后、音量标准化之前施加，所以音量仍和主音色一致。命令行：`--tune 3:formantPct=6,warmDb=-2`。不用 AI。
- **像不像主音色**：给每段打 0–100 分（音色差、共振峰偏差、音高差综合），同一句话生成多条时挑最像的；60 分以下靠处理也很难拉齐，建议重新生成。

包里已带好 Node 运行时和 ffmpeg，全程离线。程序没有购买代码签名证书，所以系统会提示一次“无法验证开发者”。详细步骤见包内的 `使用说明.txt`。

打包方法：`app.mjs` 是独立版入口，`build/bundle.mjs` 把所有模块合成一个 CommonJS 文件，`build/package.sh` 用 Node 的单文件可执行（SEA）生成 Windows exe，并组装两个 Mac 包（脚本开头写了需要预先下载的文件）。

## 在自己电脑上运行（开发者方式）

1. 安装 Node.js 24（22 及以上也可以）：https://nodejs.org ，装好后在终端运行 `node --version` 确认。
2. 把整个 `voice-unify` 文件夹拷到电脑上，在终端里进入这个文件夹。
3. 任选一种方式：

```bash
# 网页界面（推荐）：然后在浏览器打开 http://127.0.0.1:8765
node cli.mjs ui

# 命令行批处理：以 a.mp4 的音色为主，b、c 向它靠拢，输出到 out 文件夹（视频输出仍是视频）
node cli.mjs process a.mp4 b.mp4 c.mp4 -o out --ref a.mp4

# 只看指标
node cli.mjs analyze a.wav b.wav

# 用合成音频跑一遍演示，打印处理前后的指标
node cli.mjs demo
# 模拟 AI 配音：四段音高、共振峰、明亮度各不相同，外加拼好的成片走分段模式
node cli.mjs demo --ai
# 生成 3 段合成测试视频，走一遍视频流程（需要 ffmpeg）
node cli.mjs demo --video

# 自动测试
npm test
```

网页界面可以直接拖入视频（mp4、mov、mkv 等）和 mp3、m4a、flac 等音频；在“音色基准”一列选主音色那一段，点“开始处理”，再点“下载视频”。服务只监听本机 127.0.0.1，别的电脑访问不到。

## 处理视频（需要 ffmpeg）

从视频里取出音轨、再把处理好的音频放回视频，用的是 ffmpeg。它是一个独立的免费程序，同样离线运行。画面流直接复制、不重新编码，所以画质不变，处理也快；音轨编码为 AAC 256 kbps（webm 为 Opus）。

离线打包方式：在有网的电脑上下载一次 ffmpeg 的静态版本，把可执行文件放进 `voice-unify/bin/`（Windows 放 `ffmpeg.exe`，macOS/Linux 放 `ffmpeg`），之后整个文件夹拷到哪台电脑都能用，不需要安装。程序按这个顺序找 ffmpeg：环境变量 `VOICE_UNIFY_FFMPEG` → `bin/` 文件夹 → 系统 PATH。

- Windows：ffmpeg 官网 https://ffmpeg.org/download.html 链接的 gyan.dev 或 BtbN 的 “essentials / static” 版本，解压后取 `bin/ffmpeg.exe`。
- macOS：同一页面链接的静态版本，或 `brew install ffmpeg`。
- Linux：`sudo apt install ffmpeg`，或 johnvansickle.com 的静态版本。

没有 ffmpeg 时，网页界面仍能处理视频里的声音（浏览器负责解码），但只能导出音频，不能导出视频。ffmpeg 使用 LGPL/GPL 许可，如果以后要把它一起打包对外分发，需要附上它的许可说明。

### 命令行参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--ref <文件名或序号>` | 平均 | 以哪段录音的音色为基准；不填则全部向平均音色靠拢 |
| `--lufs <数值>` | -16 | 目标响度：播客/视频 -16，音乐平台 -14，广播 EBU R128 -23 |
| `--denoise <0~1>` | 0.7 | 降噪强度，0 关闭；1 时单个频点最多压低 24 dB |
| `--eq <0~1>` | 1 | 音色匹配强度，0 关闭 |
| `--pitch <0~1>` | 0 | 音高对齐强度，默认关闭 |
| `--formant <0~1>` | 0 | 共振峰对齐强度，默认关闭 |
| `--dereverb <0~1>` | 1 | 混响对齐强度，0 关闭 |
| `--segment` | 关 | 分段模式：在 0.5 秒以上的停顿处切开，每段（至少 3 秒）单独对齐，适合已经拼好的成片 |
| `--peak <dBFS>` | -1 | 峰值上限 |
| `--bits <16/24/32>` | 24 | 输出位深，32 为浮点 |

## 它做了什么

每段录音依次经过六步：

1. **降噪**：从录音里最安静的 15% 帧估计噪声频谱，再用判决引导（decision-directed）维纳滤波逐帧压低噪声，并沿频率平滑增益以减少“水声”（音乐噪声）。对稳定噪声（底噪、风扇、空调、电流嗡声）效果最好。
2. **音高和共振峰对齐**：用 YIN 算法估计每段的平均基频，和基准差 0.3 个半音以上就移调（最多 ±6 个半音）。移调用相位声码器，采用 Laroche-Dolson 的“谐波峰整体搬移 + 相位锁定”，避免普通相位声码器那种发虚、像加了混响的感觉；同时用倒谱包络把嗓音的共振峰保留在原位，所以只改音高、不会变成“卡通音”。同时比较每段和基准的平均频谱包络，估计共振峰整体偏高或偏低了多少（嗓音“胖瘦”的主要来源），偏差超过 2% 就在同一步里校正，最多 ±10%。
3. **混响对齐**：比较每段和基准的混响程度（一句话停下后声音衰减 20 dB 用的时间，以及盲估的混响时间），明显比基准“空”的段落用 Lebart 晚期混响抑制把多出来的尾音压掉，力度偏保守。
4. **音色匹配**：分别统计每段录音有声部分的长时平均频谱（1/6 倍频程，40 Hz–16 kHz，能分辨鼻音、齿音这类窄频段），和基准比较后得出一条平滑的 EQ 曲线（最多 ±12 dB），以零相位方式施加。原录音里本来没有语音的频带（比如电话录音 3.4 kHz 以上）不会被提升，否则提升的只会是噪声。
5. **响度标准化**：按 ITU-R BS.1770-4 / EBU R128 测量积分响度（K 加权、400 ms 块、-70 LUFS 绝对门限和 -10 LU 相对门限），调到目标值。
6. **峰值限制**：前瞻限制器保证没有采样超过 -1 dBFS；限制后再测一次响度并补偿。

这里的“统一音色”指让同一个人（或同一个 AI 音色）的不同片段听起来一致，**不是**把一个人的声音变成另一个人（那是 AI 变声，见下文）。

**分段模式**：如果几段已经拼成一个视频，勾选“分段模式”（命令行 `--segment`），程序会在 0.5 秒以上的停顿处把它切开（每段至少 3 秒），每段单独做音高、共振峰、音色和响度对齐，再在停顿处用 20 毫秒交叉淡化无缝拼回，长度和画面完全不变。目标默认是所有段的平均；如果想以某一段为准，可以把那段单独导出成文件一起拖进来，选它作为“音色基准”。

**默认不升调**：在用户的真实 AI 口播片段上对比试听，只调音量、音色、降噪和混响、不改音高的版本（B 版）最自然，所以“音高对齐”和“共振峰对齐”默认关闭。只有某段音高明显跑偏、又确实想拉齐时再打开。

## 合成音频上的结果

`node cli.mjs demo` 生成同一个“说话人”的四段录音：安静房间（作为基准）、手机远距离（300–3400 Hz 带宽，粉红噪声）、领夹麦（低频过重，50 Hz 电流声）、笔记本（偏亮，风扇噪声）。合成语音由带音高起伏的谐波、共振峰、音节包络和擦音组成。结果（`demo-output.txt`，试听文件在 `demo/input` 和 `demo/output`）：

| 文件 | 响度 前→后 (LUFS) | 估计信噪比 前→后 (dB) | 音色差 前→后 (dB) | 语音/停顿比 前→后 (dB) |
|---|---|---|---|---|
| 01 参考-安静房间 | -24.7 → -16.0 | 47.9 → 64.7 | 0.0 → 0.0 | 43.8 → 60.5 |
| 02 手机-离得远 | -42.0 → -16.1 | 19.3 → 28.5 | 2.2 → 0.9 | 14.2 → 19.1 |
| 03 领夹麦-电流声 | -27.6 → -16.0 | 14.4 → 34.5 | 3.5 → 1.0 | 11.5 → 30.4 |
| 04 笔记本-风扇声 | -32.2 → -16.0 | 12.1 → 26.9 | 1.7 → 1.2 | 8.1 → 18.4 |

四段之间的响度差距从 17.3 LU 降到 0.1 LU。

视频流程（`node cli.mjs demo --video`，见 `demo-video-output.txt`，视频在 `demo-video/`）：前三段配上纯色测试画面封装成 mp4，以第 1 段为主音色处理后输出 mp4，再从输出视频里重新提取音轨测量，响度都是 -16.0 LUFS，确认放回视频的就是处理后的声音。

- **估计信噪比**：不需要干净原声的盲估，50 ms 帧能量的第 90 百分位减第 10 百分位。真实录音也能看。
- **音色差**：100 Hz–8 kHz 内与基准的 1/6 倍频程频谱差（均方根，dB），只统计原录音里确有语音的频带。
- **音高差**：与基准平均基频相差的半音数。
- **语音/停顿比**：演示专用，用已知的干净原声标出说话和停顿位置，计算两处的电平差，越大说明停顿处残余噪声越少。

## 真实 AI 视频的测试

用户提供的三段 AI 口播视频（同一个声音，竖屏 720×1280，单声道内容）以 7-20-重做01 为主音色处理，结果见 `真实片段测试/说明.md`（不在压缩包里，单独交付）。测试中发现并修复了一个问题：原来统计频谱时只用最响的一半帧，齿音、擦音这类能量小的高频帧被漏掉，提升高频后它们才被算进来，导致高频被提亮过头（7-21 在 5–9 kHz 会多出 6–10 dB）。现在统计所有比响亮帧低不超过 35 dB 的帧。第二轮反馈是 7-22 升调后“带混响、音色不一样”：原片 7-22 的尾音本来就比主音色长，旧的升调算法又会让声音发虚，因此换了相位锁定的升调算法（往返测试的频谱失真从约 10 dB 降到约 5 dB），并加了混响对齐。

## AI 配音场景的结果

`node cli.mjs demo --ai`（演示里打开了音高和共振峰对齐，见 `demo-ai-output.txt`，试听文件在 `demo-ai/`）模拟同一个 AI 音色生成的四段：主音色、偏高偏亮（高 2 个半音、共振峰高 6%、高频 +5 dB）、偏低偏闷（低 1.5 个半音、共振峰低 5%、高频 -5 dB）、鼻音重（1 kHz 附近窄峰 +6 dB）。

| 文件 | 响度 前→后 (LUFS) | 音色差 前→后 (dB) | 音高差 前→后 (半音) |
|---|---|---|---|
| 01 主音色（基准） | -28.0 → -16.0 | 0.0 → 0.1 | 0.0 → 0.0 |
| 02 偏高偏亮 | -28.6 → -16.0 | 2.2 → 0.8 | 1.4 → 0.0 |
| 03 偏低偏闷 | -33.0 → -16.0 | 5.1 → 1.5 | -2.9 → 0.0 |
| 04 鼻音重 | -35.3 → -16.0 | 2.4 → 0.9 | 0.5 → 0.0 |

同样四段首尾拼成一个文件用分段模式处理：自动在段间停顿处切成 4 段，段间音高差距从 4.25 个半音降到 0.02 个，响度差距从 7.3 LU 降到 0.1 LU。

处理速度约为实时的 3 倍（1 分钟音频约 20 秒），移调这一步最耗时。

## 为什么选这个技术栈

- **Node.js 标准库 + 浏览器界面**：用户只需装一个 Node.js，没有 `npm install`、没有原生编译、没有 Python 环境冲突，Windows / macOS / Linux 同一份代码。界面就是本机网页，浏览器顺带提供了 mp3/m4a 等格式的解码。
- **以后做成双击即用的单文件程序**：可以用 Node 自带的 Single Executable Applications（SEA）把代码打进一个 `.exe` / 可执行文件，用户连 Node 都不用装；或者套一层 Electron/Tauri 做成桌面应用。核心算法都在 `lib/` 里，换外壳不需要改。

## 局限和下一步

- **非稳定噪声**（突然的人声、键盘、关门）经典方法压不掉；整段一直在说话、几乎没有停顿的录音，噪声估计会偏高。可以加入噪声跟踪（minimum statistics）或让用户手动选一段纯噪声。
- **丢掉的频带找不回**：电话录音 3.4 kHz 以上已经没有语音内容，EQ 无法还原，只能靠 AI 带宽扩展。
- **混响**没有处理；房间回声大的录音会听起来仍不一样。
- **长录音**：目前整段读入内存，适合几十分钟以内的文件；更长的需要改成流式处理。
- **升级到 AI 降噪**：可以接入本地模型，例如 RNNoise（很小，可编译成 WebAssembly 在 Node 里跑，仍然零依赖、离线）或 DeepFilterNet（效果更好，需 ONNX 运行时和模型文件）。降噪步骤是 `lib/denoise.mjs` 里一个函数，替换即可。
- **音高对齐只对齐平均音高**，不改每句话内部的语调；AI 配音偶尔出现的某个字发音怪、情绪不对，需要重新生成那一句。
- **共振峰估计**在每段至少几秒、以说话为主时比较准（合成测试误差约 2–4%）；很短的片段建议关掉“共振峰对齐”。
- **同一个人 vs 不同的人**：如果几段视频是同一个人在不同设备、不同环境下录的，上面的 EQ 匹配就能让它们听起来接近。如果是不同的人，EQ 只能让录音环境的感觉一致，嗓音本身（音高、音质、口音）不会变；要让不同的人听起来像同一个人，需要 RVC、OpenVoice 一类的本地 AI 变声模型（几百 MB 模型文件，最好有显卡），可以作为单独的一步加在流程前面。
